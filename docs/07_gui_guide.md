# 07 · GUI 使用说明 / GUI guide

```bash
python -m agentic_tts.gui                    # 默认 http://127.0.0.1:8301
python -m agentic_tts.gui --engine sine      # 不加载权重先看界面（正弦波占位）
```

界面同进程直调 `TTSModule`，**不经 HTTP** —— GUI 与 HTTP 服务是两种**并列**用法，
单机用户不必先起一个 server。

风格与 DailyNewsAssistant 工作台同一路数（`gui/theme.py`）：深底、细线网格、等宽数字、
单一强调色。**状态从不只靠颜色**，每种状态都带一个形状符号（○ 待生成 / ▶ 合成中 /
● 已生成 / ◐ 文本已改 / ▲ 失败），色觉障碍与黑白截图下都读得出来。
字体只用本机一定存在的字体栈 —— 公司代理会把 Google Fonts 拦下来。

## 顶栏

`引擎 / 设备 / 精度 / 驻留上限` + **状态灯** + 本次会话的产物目录名。

状态灯是这个界面最常被看的元素（一条合成几十秒起）：

| 显示 | 含义 |
|---|---|
| `● 就绪` | 空闲 |
| `▶ 合成中　第 2 段（共 5 段）　12.3s` | 正在跑，**带秒表**，多段时报到第几段 |
| `● 完成 5/5 段　耗时 63.4s　音频 17.32s` | 跑完 |
| `▲ 失败` | 出错（详情在弹出的通知里） |

⚠️ **耗时与音频时长是两个数**，界面上一律分开写。只写一个数字时会被当成"这次跑了多久"，
而两者差着一个数量级（CPU 上 RTF ≈ 13，一分钟音频要跑十三分钟）。
段落卡片里的 `耗时 / 音频 / RTF` 同理。

秒表和进度由一个 0.3 秒的 `ui.timer` 刷新。合成在工作线程里跑，进度经门面的
`progress` 回调写进一个字典，**回调本身不碰 UI** —— 跨线程直接改控件是不安全的。

## 页签一：单段生成

文本框 + 声音配置 + 生成。产物落在自动命名的新目录（每次点击一个，互不覆盖）。

## 页签二：多段生成

### ① 统一声音配置

顶部一组完整配置（模式 / 音色 / 语气指令 / 参考音频克隆），**默认勾选「所有段共用这套配置」**。
勾着的时候它覆盖所有段；取消勾选后，每段卡片里的「单独配置」折叠面板才生效。

统一配置与每段的单独配置是**同一份控件实现**，所以能力完全一致 ——
音色克隆、音色设计在两处都能用。

控件**按模式显隐**：只有选「音色克隆」才出现参考音频那一行（上传框被压成一条虚线细带，
文件名显示在下方），选「内置音色」时才出现音色下拉。Quasar 的上传框默认是个带标题栏
和文件列表的大盒子，常驻会占掉半屏。

### ② 一整段文本 → 自动拆条

| 规则 | 行为 |
|---|---|
| 按标点 | 一句一段（默认，不合并碎句） |
| 按字数 | 按上限切，但仍在标点处落刀，不硬切字 |
| 按角色 | 识别「角色：台词」前缀；角色→音色取自 `configs/config.yaml` 的 `voices.roles` |
| 按空行 | 作者已经分好段的情况 |

按角色拆时，**没配音色的角色会弹提示** —— 沉默地全用默认音色会让所有人听起来是同一个人，
且没有任何报错。

### ③ 每段一张卡

卡头：`第 N 段` + 状态标记 + 角色，右侧三个按钮：

- **生成本段**：只跑这一段，其他段不动；
- **换种子重掷**：同一段种子固定为 `base + 段序号`，重复生成结果一样，
  想换一版必须点这个；
- **删除**：删掉这一段（列表重建、序号重排，已生成的音频与状态会保留）。

卡内：文本框、「单独配置」折叠面板、段后停顿(ms)、本段用时/RTF/种子、播放器。

**正在合成的那张卡会高亮**（左侧琥珀色竖条 + 底色），一眼就能看到跑到哪了。

改了某段文本，状态立刻变成 `◐ 文本已改` —— 手里那条音频已经对不上稿子了，
合并时会先补跑它。

### ④ 底部两个按钮

| 控件 | 行为 |
|---|---|
| **导出字幕 SRT**（勾选框） | 合并时顺带写 `merged.srt`：**一段音频一条字幕**，时间轴含段间静音，剪映/Premiere/DaVinci 可直接导入。默认取自 `configs/config.yaml` 的 `output.subtitles` |
| **全部生成（每段单独落盘）** | 逐段合成，每段一个 wav |
| **合并成整段（复用已生成音频）** | **不重跑模型**，直接拼接已有音频；只有 `○ 待生成` / `◐ 文本已改` / `▲ 失败` 的段落才补跑，补完再拼 |

> 为什么合并要复用：重跑一段是几十秒，而且解码是**采样**的 ——
> 同一段重跑会得到和你刚试听过**不一样**的音频。「明明听着好，一合并就变了」
> 是最难解释的一类问题。拼接由 `TTSModule.merge_audio()` 完成，
> 单测用引擎调用次数（必须为 0）把这条钉死。

段间静音规则与门面一致：段落自己填的 `段后停顿` 优先，否则同角色用 `audio.pause_ms`、
换角色用 `audio.role_change_pause_ms`（换人要有可感知的间隔）。

### 产物目录

**一次会话（一次打开页面）的所有产物都在同一个目录** `outputs/gui-<时间戳>/`：
每段一个 `seg_NNN_*.wav`、合并的 `merged.wav`、字幕 `merged.srt`、以及 `manifest.json`。
逐段重做会覆盖该段自己的文件 —— 这正是要的效果，也省得十几段散在十几个时间戳目录里。

播放器旁边的 📂 图标**打开产物文件夹**。⚠️ 打开的是**跑 GUI 那台机器**上的文件管理器
（浏览器没有本地文件权限，这件事只能服务端做）；远程访问时点了不会有反应，
所以路径也一直显示在旁边，随时可复制。

## 三条实现上的注意（改 GUI 前先看）

1. **UI 必须建在 `@ui.page('/')` 里。** NiceGUI 对"自动首页"的实现是每来一个客户端就
   重跑一遍入口脚本，于是 `ui.run()` 被重复执行、页面直接 500（RAG 模块实测踩过）。
   用显式 page 装饰器后每个客户端各自拿到自己的段落状态与会话目录。
2. **合成扔线程 + 一把锁串行**（`run.io_bound` + `_LOCK`），并且**拒绝重入**：
   连点两次不只是白跑一遍 —— 两次生成会挤在同一秒建目录（曾因此互相覆盖，见
   `issues/004`），且同一张 8 GB 卡上两条请求会同时要两份权重。
3. **上传事件的形状跨 NiceGUI 大版本变过**：3.x 是 `event.file`（`read()` 是 async），
   2.x 是 `event.name` + `event.content`。代码里两种都认。

## 已知限制

- 事件标记是**追加到文本末尾**，不是插到光标处（NiceGUI 拿不到 textarea 光标位置，
  为此写自定义 JS 不值）。
- 参考音频上传后存在**服务端**的 `voices/refs/`；跨机部署时 GUI 与引擎需在同一台。
- 段落状态存在浏览器会话里，刷新页面会清空（音频已落盘，不会丢）。
- 播放器取音频时浏览器会主动断流，Windows 上会在控制台留一条
  `ConnectionResetError: [WinError 10054]` —— 那是 asyncio 的 Proactor 传输层噪声，
  与合成结果无关（栈里没有本模块的代码），产物齐全就是正常的。
