# 002 · 离线引擎的"模拟失控"钩子被之前的调用消耗掉

**状态**：已修复（`agentic_tts/engines/sine.py`）
**发现**：2026-09-07，S5 门面首跑
**影响范围**：仅测试用的 `sine` 引擎（不影响 qwen3）

## 现象

`sine` 引擎的 `_simulate_runaway: 1` 本意是「这一段的第 1 次生成返回撞上限的音频，
用来验失控重试」。实跑 `retries == 0`，重试逻辑看起来没生效。

## 原因

计数器是**按引擎实例的调用次数**算的：

```python
self._calls += 1
if self._calls <= runaway_calls:   # ← 前面已经有 4 次正常调用了
```

而引擎实例在整个进程里是复用的（门面缓存），同一次测试里前面几段已经把计数器推到 4，
于是 `4 <= 1` 为假，钩子从未触发。**钩子被无关的调用消耗掉了。**

## 修法

改成**按文本计数**：

```python
seen = self._seen.get(chunk.text, 0) + 1
self._seen[chunk.text] = seen
if seen <= runaway_calls:
```

同一段文本的前 N 次失控 —— 与"哪一段、之前跑过多少"无关，语义也更贴近用例的意图。

## 教训

测试钩子的状态要挂在**被测对象的语义单位**上（这里是"一段文本"），
不要挂在"实例生命周期内的第几次调用"上 —— 后者会被任何无关调用污染，
而失败表现是"重试逻辑好像没生效"，很容易被误判成产品代码的 bug。
